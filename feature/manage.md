# method
서버를 어떻게 모니터링 할 것인지도 효율적인 방법을 생각해내야함
지금 서버와 모니터링 서버 모두 교내망 안에 있는 형태야.
외부에 있는 서버 등에는 쉽게 접속이 가능한데, 반대로 외부에서 서버로 접근하려면 VPN이 있어야한다.
그런데 지금 이 대시보드는 외부망에 있는 서버도 모니터링을 하도록 만드려고 해서 그것도 고려를 해야한다.
대시보드 tab에 내부망/외부망을 나눠서 볼 수 있게 할 것임

실제 등록 절차와 입력 도움말은 [server_registration.md](./server_registration.md) 를 기준으로 본다.

그런데 문제는 이런 서버 등록이 다른 유저가 쉽게할 수 있어야 한다는 것이다. 
외부에 있는 서버는 보통 AWS같은 임대용 서버이고 ssh key를 등록해서 접근이 가능한 형태라는 것을 알아둬.
그리고 외부에서 모니터링 서버에 직접 접속하는 것은 불가능해.

## slack 알림 기능
마찬가지로 서버가 꺼지거나 그런 일이 발생하면 특정 채널에 알림을보내야해
DM으로 보내거나 이런 기능은 아니고 그냥 log를 기록하는 곳이 slack channel이 되는거야.
어떤 로그를 어떻게 보내야 효과적일지 고민해야해
맨날 같은 로그가 나오거나 하면 집중을 안할거아니야

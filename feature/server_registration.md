# Server Registration Guide

## 목적
- 서버 등록 시 어떤 값을 넣어야 하는지 바로 알 수 있게 한다.
- 내부망 / 외부망 절차 차이를 명확히 남긴다.
- 외부망 등록에서 빠지기 쉬운 SSH key 등록, 방화벽 개방 요청을 문서로 고정한다.

## 공통 입력값
- `서버 이름`
  - 대시보드와 Slack에 표시될 이름이다.
  - 예: `Poseidon`, `gpu-aws-a100-01`
- `호스트`
  - SSH 접속 대상 주소다.
  - 내부망: 보통 교내 IP
  - 외부망: public IP 또는 public DNS
- `SSH 포트`
  - 기본은 `22`
  - 서버가 다른 포트를 쓰면 그 포트를 입력한다.
- `SSH 유저`
  - 실제 SSH 로그인에 쓰는 계정명이다.
  - 이 계정은 GPU/시스템 수집 명령을 실행할 수 있어야 한다.
- `관리자 패스워드`
  - 모니터링 시스템에 서버를 등록/수정/삭제할 때 필요한 관리자 인증 값이다.

## 내부망 서버 등록
### 권장 흐름
1. 평소 SSH 로그인에 쓰는 계정명을 확인한다.
2. 해당 계정으로 `ssh user@host -p port` 접속이 되는지 먼저 확인한다.
3. 서버 등록 폼에서 `네트워크=내부망`을 선택한다.
4. `SSH 유저`에는 평소 로그인에 쓰는 계정을 입력한다.
5. 서버 정책에 맞게 비밀번호 또는 SSH 키를 입력한다.
6. `연결 테스트`를 통과한 뒤 저장한다.

### SSH 유저 기준
- "모니터링 전용 계정"이 따로 필요한 것은 아니다.
- 대부분은 운영자가 평소 접속할 때 쓰는 Linux 계정을 그대로 넣으면 된다.
- 예: `ubuntu`, `ircv`, `root`

### 주의
- 이 계정은 최소한 다음 정보를 읽을 수 있어야 한다.
  - GPU 사용량 (`nvidia-smi` 또는 `gpustat`)
  - CPU / RAM
  - storage usage

## 외부망 서버 등록
### 권장 흐름
1. SSH 포트 기준으로 정보통신처에 방화벽 개방 요청을 먼저 넣는다.
2. 연구실 네트워크에서 대상 서버로 실제 SSH 접속이 되는지 먼저 확인한다.
3. 모니터링에 사용할 대상 계정을 정한다.
4. 그 계정의 `~/.ssh/authorized_keys` 에 공개키를 등록한다.
5. 서버 등록 폼에서 `네트워크=외부망`을 선택한다.
6. `SSH 유저`에는 공개키를 등록한 동일한 계정명을 입력한다.
7. 인증 방식은 `SSH 키`를 선택한다.
8. 폼의 `SSH 키` 칸에는 공개키가 아니라, 그 공개키와 짝이 되는 개인키를 붙여넣는다.
9. `연결 테스트`를 통과한 뒤 저장한다.

### SSH key 기준
- 서버 쪽에 등록하는 값: 공개키 (`id_ed25519.pub` 같은 `.pub`)
- 모니터링 폼에 입력하는 값: 개인키 (`-----BEGIN ...-----`)
- 즉, 폼은 `public key` 입력란이 아니다.

## 연결 테스트 실패 시 먼저 볼 것
- `SSH 유저`가 실제 로그인 계정명과 같은지
- 외부망이면 `authorized_keys` 등록 계정과 폼의 `SSH 유저`가 같은지
- 외부망이면 개인키/공개키를 반대로 넣지 않았는지
- 외부망이면 방화벽 개방이 완료됐는지
- 포트가 `22`가 아닌데 기본값으로 둔 것은 아닌지

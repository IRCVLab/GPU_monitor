# 인증 설계

## 결정: 계정 시스템 없음

로그인/계정 없음. 대시보드는 완전 공개 접근.
쓰기 작업(메모, 서버 등록 등)에만 인라인 패스워드 입력.

---

## 쓰기 작업 인증 방식

### 메모 작성/삭제

- 메모 작성 시 사용자명 + 비밀번호 입력란 포함
- 비밀번호는 서버 SSH 크리덴셜로 검증 (v1 방식 계승)
  - 등록된 서버 중 하나에 SSH 로그인 성공하면 유효한 사용자로 인정
- 관리자 마스터 패스워드로 모든 메모 삭제 가능
- 메모에 `username` 기록 → 본인 메모만 삭제 가능 (또는 마스터)

### 서버 등록/수정/삭제

- 마스터 패스워드 입력으로만 가능 (관리자만)
- 환경변수 `ADMIN_PASSWORD`로 설정

### UI 패턴

```
[메모 남기기 ▼]

이름: [________]  비밀번호: [________]
내용: [________________________]
                              [작성]
```

모달이나 별도 페이지 없이 인라인으로.

---

## 서버 SSH 크리덴셜 보안

SSH 접속 정보는 DB에 저장되어야 하므로 암호화 필수.

```
저장 형태:
  - password:    AES-256 (Fernet) 암호화
  - private key: AES-256 (Fernet) 암호화

암호화 키: 환경변수 SECRET_KEY에서 파생
```

- SSH 크리덴셜은 백엔드에서만 사용 (수집 루프)
- API로 평문 크리덴셜 반환 절대 금지
- 서버 조회 응답에는 `has_password` / `has_key` 불리언만 반환

---

## 환경변수 설정

```env
SECRET_KEY=<32바이트 이상 랜덤 문자열>   # SSH 크리덴셜 암호화용
ADMIN_PASSWORD=<관리자 마스터 패스워드>   # 서버 관리, 전체 메모 삭제용
```
